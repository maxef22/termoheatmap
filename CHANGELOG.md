# История изменений

Версия соответствует `<version>` в `web/info.xml`.

## 1.1.2 — 2026-11-20

Исправления по результатам разбора кода версии 1.1.1. В скобках — номер замечания из
`Termoheatmap_1.1.1_review.md`.

### Данные

- **Только реальные измерения (C2).** В расчёт попадают сэмплы с `TrendType.DATA`;
  служебные метки тренда (`COMMUNICATIONS_DOWN`, `GATEWAY_DOWN`, `DEAD`, `UNKNOWN_VALUE`,
  `FAILURE`, `DATATYPE_MISMATCH`, …) больше не превращаются в температуру 0 °C.
  Дополнительно отсекаются сэмплы с ненулевым `getSpecialValue()`.
- **Один часовой пояс на весь аддон (C3).** Убрано жёсткое смещение `+3 часа`. Дата
  разбирается, час считается и «сегодня» определяется в одной зоне
  (`com.controlj.addon.temperature.util.AddonTime`, по умолчанию `Europe/Moscow`,
  переопределяется `-Dtermoheatmap.timezone=<зона IANA>`). Раскладка по часам больше не
  зависит от часового пояса JVM сервера.
- **Правая граница суток (F3).** Сэмпл ровно в 00:00 следующего дня не попадает в час 0.
- **`0.0 °C` — это значение (F4).** Проверки `if (percentile95)` заменены на проверку
  на `null`: ноль больше не считается «нет данных».
- **Тренд отключён (Q11).** Вместо «нет данных» возвращается понятная причина.
- **Ошибка одного датчика не роняет остальные (C5).** `hasAspect()` перед `getAspect()`,
  отказ по конкретной точке попадает в её поле `error`.

### Устойчивость

- **Нет гонки в форматтере даты (C1).** `SimpleDateFormat` в поле сервлета заменён на
  неизменяемый `DateTimeFormatter`; строгий разбор даты (Q5).
- **Валидный JSON ошибок (C4, F12).** Общий `JsonResponse`: текст ошибки никогда не бывает
  пустым (`put(key, null)` в org.json удаляет ключ, из-за чего клиент получал `{}`),
  учитывается `isCommitted()`.
- **Ошибки пишутся в лог сервера** (`log(...)`), а не в `System.out`.

### Интерфейс

- **«Сегодня» и «текущий час» приходят с сервера (C6).** Раньше дата считалась по UTC:
  в Москве с 00:00 до 02:59 подставлялось вчерашнее число и не гасились будущие часы.
- **Дерево датчиков по путям локаций (F1, F2).** Второй датчик в комнате больше не теряется,
  одноимённые комнаты не сливаются, датчик верхнего уровня виден. Подпись строки: имя
  комнаты, а при нескольких датчиках — «комната · точка».
- **Один запрос на все комнаты (F9).** «Показать все номера» больше не делает N
  последовательных запросов: сервлет `/temperature/data` принимает `ids` и читает все
  тренды в одном `runReadAction`.
- **Единая палитра и легенда (F5).** Убран скачок цвета на 21.0 °C; градиент легенды
  строится из того же массива порогов, что и цвет ячеек. Цвет текста выбирается по яркости
  фона (на синем и красном читается).
- **Меньше трафика (F10).** Сырые сэмплы отдаются только по `debug=1`.
- **`max` у поля даты (Q6)** — будущие даты выбрать нельзя.
- **JavaScript в стиле ES5 + `XMLHttpRequest` (Q13)** — страница работает и в старых
  браузерах (IE11).

### Поиск датчиков

- **Точное совпадение по умолчанию (F6, Q9).** Маска `zone_temp` больше не находит
  `zone_temp_sp`, `zone_temp_setpoint`, `zone_temp_avg`. Режим сравнения выбирается в
  интерфейсе: `exact` / `contains` / `regex`. Жёсткий «чёрный список» имён удалён.
- **Одинаковые права на поиск и данные (F7).** Поиск и дерево работают под соединением
  оператора, а не под root: аддон не показывает локации, закрытые для оператора, и не
  отдаёт ошибки по недоступным точкам.

### Упаковка и эксплуатация

- **Удалён неиспользуемый `TemperatureAggregateServlet` (F8, Q14)** — он нигде не вызывался,
  а часы в нём считались в UTC; вместе с ним ушло усреднение «среднее по средним».
- **Одна версия во всех местах (Q2):** `info.xml`, имя проекта, имя war.
- **`@WebServlet` убраны (Q1)** — сервлеты объявлены только в `web.xml`.
- **`debug.jsp` вынесен в `tools/` (Q3)** и не попадает в поставку; `index.html`-заглушка
  удалена.
- **Целевая версия Java — 11 (Q12).** Проверка показала, что `javac.target=8` не имеет смысла:
  сам SDK `directaccess-api-addon-1.7.0.jar` скомпилирован под Java 11 (class file 55), и на JVM 8
  аддон падает с `UnsupportedClassVersionError` ещё при развёртывании. `javac.source/target=11`
  соответствует SDK и верхней границе WebCTRL; проверено на AdoptOpenJDK 11.0.2.
- **`Cache-Control: no-store`** на JSON-ответах (Q8).
- **Идентификаторы — reference-пути (Q7)**: ручная сборка `ABSPATH:1:#…` удалена,
  пути и `id` строятся из `getReferenceName()` по дереву (как и раньше, `Tree.resolve()`
  их принимает).
- Удалён неиспользуемый `parentName` (Q4), расчёт процентиля сведён в `util/Stats` (Q10),
  `Context path` приведён к имени файла аддона.

### Известные ограничения

- Зона аддона по умолчанию — `Europe/Moscow`. Для объекта в другом поясе задайте
  `-Dtermoheatmap.timezone=Europe/Kaliningrad` (или другую зону IANA) в параметрах JVM WebCTRL.
- За один запрос можно запросить не более 100 датчиков (ограничение длины URL у Tomcat); страница делит выборку на порции по 50. Поиск отдаёт не более 2000 точек.
